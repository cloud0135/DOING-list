# Todo 핵심 동작 규칙

이 문서는 DOING-list 1차 MVP의 Todo 기능을 구현할 때 사용하는 기준을 정의한다.
1단계에서는 메모리 상태에서 아래 규칙을 구현하고, 영구 저장은 다음 단계에서 추가한다.

## 1. Todo 완료 상태

- Todo는 체크리스트와 별개인 `isCompleted` 값을 가진다.
- 새 Todo의 `isCompleted` 기본값은 `false`다.
- 사용자가 완료 또는 완료 취소를 명시적으로 선택할 때만 값이 변경된다.
- 체크리스트를 모두 완료해도 Todo는 자동으로 완료되지 않는다.
- 체크리스트가 없는 Todo도 완료할 수 있다.
- 진행 중 개수와 마감 일정은 `isCompleted === false`인 Todo를 기준으로 계산한다.
- 완료된 Todo는 목록에서 제거하지 않고 완료 상태를 시각적으로 구분한다.

## 2. 체크리스트 진행률

- 체크리스트 진행률은 완료한 항목 수를 전체 항목 수로 나누어 계산한다.
- 체크리스트가 없으면 진행률은 0%다.
- 체크리스트 진행률은 Todo의 완료 상태를 자동으로 변경하지 않는다.
- 빈 제목의 체크리스트 항목은 저장하지 않는다.

## 3. 정렬

- 기본 정렬은 마감일이 빠른 순이다.
- 마감일이 없는 Todo는 마감일이 있는 Todo 뒤에 표시한다.
- 마감일이 같으면 먼저 생성된 Todo를 먼저 표시한다.
- 생성일순은 최신 Todo를 먼저 표시한다.
- 제목순은 한국어 로케일 기준 오름차순으로 표시한다.
- 결과가 같은 경우 생성일과 ID를 차례로 비교해 순서를 안정적으로 유지한다.
- 1차 MVP에서는 정렬 방향을 사용자가 변경하지 않는다.

## 4. 식별자

- Todo ID와 체크리스트 ID는 `crypto.randomUUID()`로 생성한 문자열 UUID를 사용한다.
- 생성된 ID는 수정 과정에서 다시 만들지 않는다.
- 라우트의 `todoId`는 문자열로 비교하며 숫자로 변환하지 않는다.
- GitHub 리포지터리 ID는 GitHub API가 제공하는 숫자 ID를 유지한다.

## 5. 날짜와 시간

- `dueDate`는 `YYYY-MM-DD` 문자열 또는 `null`이다.
- `createdAt`과 `updatedAt`은 UTC 기준 ISO 8601 문자열로 저장한다.
- Todo 내용, 완료 상태 또는 리포지터리 연결이 변경되면 `updatedAt`을 갱신한다.
- 마감일은 선택 항목이며 입력하지 않아도 저장할 수 있다.

## 6. 입력 검증

- Todo 제목은 앞뒤 공백을 제거한 뒤 저장한다.
- 공백을 제거한 제목이 비어 있으면 저장하지 않는다.
- 체크리스트 제목도 앞뒤 공백을 제거한다.
- 빈 체크리스트 행은 생성 시 제외한다.
- 체크리스트가 없는 Todo도 정상적인 Todo로 취급한다.

## 7. 삭제

- 삭제 전에 사용자 확인을 받는다.
- 확인한 Todo는 현재 상태에서 완전히 제거한다.
- 삭제 후에는 Todo 목록으로 이동한다.
- 삭제된 Todo 주소에 접근하면 찾을 수 없음 화면을 표시한다.

## 8. 1단계 범위 밖의 기능

- `localStorage` 저장과 복원
- Supabase 데이터 저장
- GitHub OAuth와 실제 리포지터리 조회
- 비회원 데이터와 계정 데이터 병합
- 서버 동기화와 오프라인 처리

위 기능은 Todo 핵심 동작이 메모리 상태에서 검증된 뒤 순서대로 구현한다.
