# DOING-list (진행도 투두리스트)

> 계획 단계를 단축하고 실행 지연을 막아주는 '진행도 게이지 바' 기반의 실용적인 PWA 웹앱 투두리스트
> 
> 

## 현재 MVP 방향

고객은 앱 설치 과정 없이 웹 브라우저를 통해 접속하며, PWA 서비스 워커를 통해 오프라인 상태에서도 앱처럼 서비스를 이용한다. 초기 진입 시 비회원(Guest) 상태로 기기 로컬 스토리지에 할 일을 저장하며, 로그인 시 기존 로컬 데이터를 Supabase DB로 단순 병합(Append)하여 마이그레이션한다.

메인 화면에서는 모든 하위 업무의 달성 비중을 동일하게 계산하여, 하위 투두리스트 완료 시 화면 깜빡임 없이 상위 투두리스트의 진행률(%) 게이지 바가 즉각적으로 업데이트된다. 복잡도와 피로도를 낮추기 위해 사용자가 가중치를 직접 설정하는 기능이나 무거운 AI 요약/추천 기능은 제외되었으며, 오직 직관적인 시각화와 맞춤형 템플릿(예: 대학생 과제 준비 등) 제공이라는 본질에 집중한다.

```text
사용자 입력 (온/오프라인 환경)
  → 프론트엔드 상태(Zustand) 즉각 업데이트 및 화면(게이지 바) 렌더링[cite: 2]
  → 비회원: 브라우저 localStorage에 CRUD 처리[cite: 2]
  → 회원(온라인): Supabase DB로 동기화[cite: 2]
  → 회원(오프라인): localStorage 임시 저장 후 온라인 감지 시 DB 병합[cite: 2]

```

## 사용자 흐름

| 화면 | 사용자 경험 |
| --- | --- |
| **S01. Login Screen** | 중앙에 위치한 앱 로고와 이메일/비밀번호 칸, 카카오/구글/깃허브 소셜 로그인 및 비회원 시작 버튼을 통해 서비스에 진입한다. 자잘한 텍스트는 전부 배제된다.

 |
| **S02. Main Todo Screen** | 상위 투두리스트와 실시간 진행도 게이지 바를 확인한다. 진행 상황 변경 시 즉각 반영되며, 전체 마감일을 확인하고 설정 버튼으로 뷰 모드(목록형/카드형)와 정렬 순서(이름/날짜/마감일순)를 변경한다.

 |
| **S03. Sub-checklist Screen** | 특정 상위 체크리스트를 누르면 진입하여, 세부 하위 체크리스트들을 추가, 수정, 삭제한다. 불필요한 설정은 배제하고 뒤로 가기 버튼과 하위 목록 관리에만 집중한다.

 |
| **S04. Archive Screen** | 과거 100% 달성한 상위 투두리스트 목표들을 확인할 수 있는 기능으로, 지난 성실함을 직관적으로 되돌아본다. |

화면 전환은 SPA 기반으로 이루어지며, 목록형/카드형 뷰 모드 및 다크모드/라이트모드(prefers-color-scheme 기반 자동 감지) 전환은 페이지 이동 없이 한 화면 내에서 즉각적으로 부드럽게 변경된다.

## 데이터 수명과 개인정보

| 데이터 | 처리 원칙 |
| --- | --- |
| 회원 계정 정보 | Supabase Authentication을 통해 카카오, 구글, 깃허브 등 소셜 로그인과 이메일/비밀번호만 수집하며, 보안 위험이 있는 학교 LMS 정보(학번/비밀번호)는 일절 수집하지 않는다.

 |
| 비회원 투두 데이터 | 사용자의 기기 브라우저(localStorage)에만 영구 보관되며, 서버로 전송되지 않는다.

 |
| 회원 투두 데이터 | 로그인 시 기기 내부 데이터를 Supabase DB로 단순 병합(Append)하여 보관하며, 기기 내 임시 데이터는 마이그레이션 후 안전하게 폐기(clear)한다.

 |
| 오프라인 캐시 | PWA Service Worker를 통해 앱 UI 리소스는 'Cache First', 사용자 할 일 데이터는 'Network First' 전략을 적용하여 통신 단절 시 기기에 임시 수명으로 저장한다.

 |

## 현재 상태와 구현 경계

문서 기준선은 WBS 상의 '기획 및 설계' 단계이며, 현재 핵심 기능 정의와 기술 스택 확정을 완료한 상태다.

* 순수 HTML/JS 대신 TypeScript, React, Zustand, Tailwind CSS로 프론트엔드 스택 확정


* 백엔드는 BaaS인 Supabase를 연동하여 소셜 로그인 및 DB CRUD 통합


* 가비아 도메인 구매나 고정 IP 설정 없이 GCP (Firebase Hosting)를 이용한 무료 웹 배포 아키텍처 확정


* 사용자 기기 테마 설정을 감지하는 자동 다크모드 지원


* LMS 직접 연동 및 AI(OpenAI/Gemini) 요약 기능은 리스크 관리 및 MVP 집중을 위해 우선순위에서 제외 및 후순위 도전 과제로 연기



현재 디자인 컴포넌트 렌더링 확인과 투두리스트 핵심 로직 구현을 1순위 목표로 하고 있으며, 이후 상태 관리(Zustand)와 웹 푸시 알림(Web Push API)을 순차적으로 결합할 예정이다.

## Frontend 로컬 실행

Vite 기반의 React 환경을 사용한다.

```bash
npm create vite@latest doing-list -- --template react-ts
cd doing-list
npm install
npm install zustand vite-plugin-pwa
npm run dev

```

웹앱은 기본적으로 `http://localhost:5173`에서 실행된다. 백엔드 연동을 위해서는 Supabase 설정 및 `.env` 파일 구성이 선행되어야 한다.
